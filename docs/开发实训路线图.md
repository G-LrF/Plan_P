## 第 0 章：先回答你最关心的问题

### Q1：什么样才算"完成了"？

新手最容易卡住的地方是"不知道终点在哪"，于是永远在改细节。所以先把终点定义清楚。

**项目共分 5 个等级（L1→L5），每一级都有可验收的标准。** 不是"做完某个功能"，而是"达到某个等级"。

| 等级 | 一句话定义 | 能不能写简历 | 预计耗时 |
|---|---|---|---|
| **L1 能跑通的产品** | 换台电脑按文档能起来，数据不丢，有登录，完整增删改查 | ✅ 能写"全栈项目" | 4~6 周 |
| **L2 有质量保障** | 有自动化测试 + CI 流水线，改代码自动跑测试 | ✅ 能写"工程化能力" | 2~3 周 |
| **L3 能在线访问** | Docker 镜像 + 部署到服务器，有域名能打开 | ✅ 能写"部署运维" | 2~3 周 |
| **L4 云原生** | K8s 集群部署、滚动更新、健康检查、监控 | ✅ 能写"云原生"（高薪岗硬通货） | 4~6 周 |
| **L5 有 AI 能力** | 接入大模型，实现"自然语言建计划/智能拆分" | ✅ 能写"AI 应用开发"（2026 最值钱） | 3~5 周 |

**你的简历可以这样写（达到不同等级对应不同说法）**

```text
【达到 L1】
  计划规划执行系统（全栈）· Vue3 + FastAPI + MySQL
  - 独立完成前后端分离架构设计，实现 JWT 鉴权与 RESTful API
  - 使用 SQLAlchemy 设计数据模型，支持计划的分层管理与状态流转

【达到 L3】（在上面基础上加）
  - 使用 Docker 多阶段构建将前后端镜像体积压缩 xx%
  - 通过 Nginx 反向代理 + HTTPS 完成生产环境部署

【达到 L4】
  - 基于 Kubernetes 完成服务编排，配置 Liveness/Readiness 探针与 HPA 自动扩缩容
  - 使用 Helm 管理多环境部署，实现滚动更新零停机

【达到 L5】
  - 接入大模型 Function Calling，实现自然语言驱动的计划创建与任务拆解
```

### Q2：必须做的事情清单（不分等级，全都要）

这些都是"企业级"和"学生作业"的分界线：

1. **Git 规范提交**（feat/fix/chore 前缀，一个提交只做一件事）
2. **README 能让陌生人跑起来**（这条被 90% 的人忽略，但面试官一定会试）
3. **`.env` 管理配置，密码不进代码库**
4. **接口文档**（FastAPI 自带 Swagger，要用起来）
5. **错误处理**（不是每个错误都返回 500）
6. **数据库迁移**（改了表结构要能复现，不能靠手改）

## 第 1 章：开发从 0 到 1 的完整流程（这是你最该背下来的部分）

**核心认知：写代码只占真实开发时间的 30%，剩下 70% 是这些事。**

真实企业里，做任何一个功能都走这 8 步。**顺序不能乱，尤其是第 1~3 步，跳过去的人一定会在第 6 步返工。**

```text
① 需求拆解  →  ② 表结构设计  →  ③ 接口契约  →  ④ 后端实现
                                        ↓
⑧ 部署上线  ←  ⑦ 联调测试   ←  ⑥ 前端实现  ←  ⑤ 后端自测
```

下面用「给计划加一个"截止日期"字段」这个真实需求，把 8 步完整走一遍。

### ① 需求拆解（30 分钟，想清楚再动手）

**要问自己的话**：用户到底要什么？边界在哪？

| 问题 | 本例答案 |
|---|---|
| 用户要什么？ | 计划能设截止日期，快到期的有提醒 |
| 截止日期精确到日还是时分？ | 精确到日（简化） |
| 能不能不填？ | 可以不填（老数据不能坏） |
| 过期了怎么显示？ | 标红 |
| 时区怎么处理？ | **先存 UTC，前端按浏览器时区显示**（这是最容易埋雷的地方） |

> **真实案例**：某公司做"截止日期"没考虑时区，用户在中国设 23:00 截止，
> 服务器在美国按 UTC 判断，结果用户收到"已过期"提示时还剩 8 小时。
> **时区问题一定要在设计阶段想，事后改要动数据库和所有查询。**

### ② 表结构设计（写好 SQL，不要先写代码）

```sql
-- 关键决策必须在注释里写清理由，三个月后你会感谢自己
ALTER TABLE plans
  ADD COLUMN due_date DATE NULL DEFAULT NULL
    COMMENT '截止日期（只到日，不含时分；NULL 表示不限）
             ⚠️ 不用 DATETIME 的原因：产品需求只到天，用了 DATETIME
             反而会引入"今天 00:00 算不算过期"这类无意义争议';
```

**设计时要自问**：
- 这个字段能是 NULL 吗？（能，否则老数据迁移会失败）
- 需要索引吗？（如果要按日期排序/筛选，`ADD INDEX idx_due_date (due_date)`）
- 类型选对了吗？（日期用 `DATE`，时间戳用 `DATETIME`，不要用字符串）

### ③ 接口契约（先写文档，前后端才能并行）

```text
PUT /api/plans/{id}
请求体: { title, content, status, dueDate: "2026-11-30" | null }
响应:   { id, title, content, status, dueDate, createdAt, updatedAt }
错误:   404 计划不存在
        422 dueDate 格式不是 YYYY-MM-DD
```

**为什么先定契约**：定完之后，前端可以先用假数据把界面写完，后端可以独立写完接口。两人不用互相等。**这就是"并行开发"能成立的全部原因。**

### ④ 后端实现（按层写，一层只干一件事）

```text
schema.py     → 加 due_date 字段与校验（格式必须是日期）
crud.py       → 加数据库读写逻辑
routers/      → 接口函数（只负责接参、调 crud、返回）
```

**纪律**：每写完一个接口，**立刻**用 Swagger（http://127.0.0.1:8000/docs）点一遍。不要攒到后面一起调。

### ⑤ 后端自测（写脚本，不靠手点）

```python
# 一条命令跑完所有检查
python tests/test_api.py
```

**要先测什么**：
- 正常流程（传了日期）
- 不传日期（老数据兼容）
- 日期格式错误（应 422）
- 不存在的 ID（应 404）

### ⑥ 前端实现（只改 2 个文件）

```text
src/api/plan.js   → 接口函数加一个参数
src/App.vue       → 界面上加个日期选择器，渲染时判断是否过期
```

**纪律**：前端**不许**直接写 `fetch`，必须走 `api/plan.js`。

### ⑦ 联调测试（用眼睛看，用工具查）

- 打开浏览器 F12 → Network 面板
- 点一遍所有按钮，看每个请求的状态码和返回内容
- **必须看的**：请求体对不对、返回结构对不对、出错时界面提示是否友好

### ⑧ 部署上线

- 打包 → 构建镜像 → 推送仓库 → 服务器拉取 → 重启
- 上线后立刻验证：健康检查接口是否 200，核心功能是否可用

> **这就是"开发流程"。你现在缺的不是技术，是这套流程意识。**
> 有了它，学任何新技术都是把某个步骤换个工具，而不是重新学一遍开发。

## 第 3 章：阶段路线图（按顺序做，不要跳）

### 阶段 0：工程地基（1 天）—— 先做这个，不做后面全是白干

| # | 任务 | 验收标准 | 为什么必须先做 |
|---|---|---|---|
| 0.1 | 首次 Git 提交，拆成 3 个语义化提交 | `git log` 有 3 条清晰记录 | 没有版本控制，改坏了救不回来 |
| 0.2 | 写 README.md（安装、启动、测试三步） | 陌生人能照做跑起来 | 面试官一定会试这一步 |
| 0.3 | 清理遗留进程与临时目录 | 8000/8001 端口无旧进程 | 避免"改了代码没生效"的幻觉 |

> **经验之谈**：90% 的初学者跳过阶段 0，然后在阶段 3 后悔。
> 因为那时候代码已经很多，`git init` 上来一大坨，反而更不想整理。

### 阶段 1：数据库化（1~2 周）→ 达成 L1 的核心

| # | 任务 | 关键技术 | 验收标准 |
|---|---|---|---|
| 1.1 | 安装驱动、设计表结构 | SQLAlchemy, PyMySQL | 表建好，`DESCRIBE plans` 结构正确 |
| 1.2 | 用 ORM 替换内存列表 | SQLAlchemy Model | 重启服务数据还在 |
| 1.3 | 引入数据库迁移 | Alembic | 改表结构能用命令复现 |
| 1.4 | 补充契约字段 | 加 `category`、`due_date`、`created_at`、`updated_at` | 前端"设计债"正式还清 |
| 1.5 | 数据层测试 | 独立测试库 | 测试不再污染真实数据 |

**阶段 1 结束标志**：杀掉后端进程重启，数据依然在。

### 阶段 2：用户与鉴权（2 周）→ L1 收尾

| # | 任务 | 关键技术 | 验收标准 |
|---|---|---|---|
| 2.1 | 用户表 + 注册登录 | 密码必须 bcrypt 加盐哈希 | 数据库里看不到明文密码 |
| 2.2 | JWT 签发与校验 | python-jose / PyJWT | 无 token 访问接口返回 401 |
| 2.3 | 数据隔离 | 每个用户只看自己的计划 | 用户 A 拿不到用户 B 的数据 |
| 2.4 | 前端登录页 + token 管理 | 请求拦截、401 跳登录 | 刷新页面登录态保持 |
| 2.5 | 前端路由 | vue-router | 未登录访问首页自动跳登录 |

**这里有个大厂必考的坑**：2.3 数据隔离。很多新手只做了登录，却没在查询里加 `WHERE user_id = ?`，导致**越权访问**——这是真实的安全事故，简历上写"实现了鉴权"却漏了这个，面试一问就露。

### 阶段 3：测试与 CI（1 周）→ L2

| # | 任务 | 验收标准 |
|---|---|---|
| 3.1 | 后端 pytest 组织测试 | `pytest` 一条命令跑完 |

### 阶段 4：容器化（1 周）→ L3 前置（**需先装 Docker Desktop**）

| # | 任务 | 关键技术 | 验收标准 |

## 第 4 章：每天开工前 3 分钟要做的事

**这是你最需要养成的习惯，比学任何技术都重要。**

```text
1. 打开 docs/项目状态与交接.md 的「当前进度」一节，看自己停在哪
2. 打开「下一步待办」，选中今天要做的那一条
3. 开工前先跑一次测试，确认起点是干净可用的
```

**收工前 3 分钟**：

```text
1. 更新 docs/项目状态与交接.md 的进度和下一步
2. git commit（写清今天做了什么、为什么）
3. 如果遇到坑，记进「踩坑记录」—— 同一个坑不踩第二次
```

**为什么必须做这件事**：开发最大的成本不是写不出来，是**忘了自己写到哪了**。
休息三天回来，面对一堆代码完全想不起当初为什么这么写——这不是记性问题，是流程问题。

## 第 5 章：给你的学习纪律（说点不好听的）

1. **不要跳阶段。** 想先做 K8s 不做数据库，等于装修卫生间不接水管。
2. **不要一次学三个新东西。** 一个阶段只引入一个新工具，其余保持熟悉的技术。
3. **不要复制粘贴看不懂的代码。** 抄可以，但抄完必须能讲清每一行在干什么，否则就去找懂为止。
4. **不要攒需求。** 每个功能走完完整的 8 步，做完一个提交一次。
5. **报错先读十秒。** 90% 的错误信息已经告诉了你答案，只是你没读完。
6. **"能用"优先于"优雅"。** 先让它跑起来，再重构。跳过前者的人永远到不了后者。
7. **记下所有踩过的坑。** 你未来的价值很大一部分来自"我踩过这个坑"。

## 附录：技术选型为什么是这样

| 选择 | 理由 | 什么情况下该换 |
|---|---|---|
| FastAPI | 自带 Swagger、类型校验、异步性能好，2026 主流 | 团队已有 Django 遗产代码 |
| SQLAlchemy | Python 事实标准 ORM，大厂普遍使用 | 极简项目可直接用 `sqlite3` |
| Vue 3 组合式 API | 上手比 React 平缓，中文资料多 | 公司技术栈是 React（那还是要学 React） |
| Vite | 启动秒级，现代标准 | 无 |
| Docker | 容器化事实标准，没有替代品 | 无 |
| Kubernetes | 云原生事实标准 | 小项目用 Docker Compose 就够，别硬上 K8s |
| Nginx | 反向代理事实标准 | 无 |

> **最后一句**：这些工具里，**没有一个是你现在就要全学会的**。
> 按阶段走，每个阶段只学一个。焦虑来源于一次想看完全部。
