# 交接模板 · 每轮训练收工前照着填

> **用法**：把本文件复制到 `docs/会话记录_YYYY-MM-DD.md`，按下面的模板填写。
> 填完记得同步更新 `docs/项目状态与交接.md` 的「当前进度」和「当前待办」。
>
> **为什么要有这个模板**：开发最大的成本不是写不出来，是**忘了写到哪了**。
> 隔三天回来，面对一堆代码完全想不起当初为什么这么写 —— 这不是记性问题，是流程问题。

---

## 模板正文（复制以下内容开始填写）

```markdown
# 会话记录 · YYYY-MM-DD

## 一、本次会话目标
> 开工前想清楚：这一轮只做哪一件事？（一句话）
```

## 填写示例（供参考）

```markdown
# 会话记录 · 2026-10-15

## 一、本次会话目标
把 plans 数据从内存列表迁移到 MySQL，做到"杀掉后端进程重启后数据还在"。

## 二、起点状态
- 后端测试：32 项通过 / 0 项失败
- 前端构建：成功
- Git 状态：3 个 commit，工作区干净

## 三、本次实际做了什么

### 改动清单
| # | 文件 | 动作 | 改了什么、为什么 |
|---|---|---|---|
| 1 | backend/requirements.txt | 修改 | 加 sqlalchemy>=2.0 + pymysql>=1.1，接数据库必需 |
| 2 | backend/app/database.py | 新增 | 创建 Engine/Session，集中管理数据库连接 |
| 3 | backend/app/models.py | 新增 | Plan ORM 模型，映射 plans 表 |
| 4 | backend/app/main.py | 修改 | 把内存 plans[] 替换为数据库查询 |

### 关键决策与理由
| 决策点 | 选了 | 放弃了什么 | 理由 |
|---|---|---|---|
| ORM 还是裸 SQL | SQLAlchemy | 裸 sqlite3/pymysql | 团队协作可读性更好，后续换库只改连接串 |
| 同步还是异步驱动 | 同步(pymysql) | asyncmy | 当前并发量低，同步实现更简单不易出错 |
| 是否立刻上 Alembic | 先手写建表 SQL | Alembic | 表结构还会变，等稳定了再上迁移工具 |

## 四、测试结果

| 测试 | 命令 | 结果 | 退出码 |
|---|---|---|---|
| 后端测试 | python tests\test_api.py | 32 项通过 | 0 |
| 持久化验证 | 手动：创建→杀进程→重启→查询 | 数据仍在 | - |

### 未验证的部分
- 未测试并发写入（多个请求同时创建计划）
- 未测试数据库断连时的降级表现

## 五、新产生的问题 / 技术债
| # | 问题 | 严重度 | 建议处理时机 |
|---|---|---|---|
| 1 | 测试仍连着开发库，会污染数据 | 🟡中 | 阶段 1.5 |

## 六、本轮的坑

| 现象 | 根因 | 解决办法 |
|---|---|---|
| `Access denied for user 'root'@'localhost'` | MySQL 8 默认加密方式与 pymysql 不兼容 | 连接串加 `?auth_plugin=mysql_native_password` |
| 中文存入数据库后变成 `???` | 建表时没指定字符集，默认不是 utf8mb4 | `CREATE DATABASE ... CHARACTER SET utf8mb4` |

## 七、下一轮建议
**下一步做**：把测试改用独立的测试数据库（阶段 1.5）。
**不要做**：暂时不要接用户登录，先把数据层彻底稳定。
**预计耗时**：2 小时

## 八、更新检查清单
- [x] 进度已更新
- [x] 待办已勾选
- [x] 踩坑记录已补充
- [x] 已 commit：`feat(db): 计划数据迁移到 MySQL`
- [x] 测试重跑通过
```

## 一条给你的提醒

**这个模板看起来啰嗦，但它能救你的时间和心态。**

真实企业里，一个功能做完要写"变更记录"、"测试报告"、"上线清单"，
不是为了应付流程，是因为**没有这些，团队就没法协作，也没法回溯**。

你现在一个人做项目，觉得"我自己记得住"。
但实际情况是：休息一周后你连"上个月为什么把接口改成 /api 前缀"都想不起来，
然后就会犯第二个错 —— 把它改回去。

**写下来，是给未来的自己省时间。**
