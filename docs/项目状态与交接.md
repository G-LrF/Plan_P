### 数据契约（改接口前必读）

```text
GET    /api/health                    -> { status, service }
GET    /api/plans                     -> { total, data: Plan[] }
GET    /api/plans/search?keyword= kw  -> { keyword, total, data: Plan[] }
GET    /api/plans/{id}                -> Plan | 404
POST   /api/plans   body{title,content}            -> 201 + Plan
PUT    /api/plans/{id} body{title,content,status}  -> Plan | 404
DELETE /api/plans/{id}                -> { message, data: Plan } | 404

Plan = { id: int, title: str, content: str, status: 0|1 }
       status: 0=未完成, 1=已完成
       id 由后端生成，客户端不可指定
```

## 五、技术铁律（违反会导致返工，务必遵守）

1. **前端所有网络请求必须写在 `frontend/src/api/plan.js`**，组件里禁止出现 `fetch`。
2. **前端 URL 一律用相对路径 `/api/...`**，禁止写死 `http://127.0.0.1:8000`（否则上线换域名全站挂）。
3. **`id` 由后端生成，客户端不许传**（防止主键冲突与越权覆盖）。
4. **前端不重复写后端已有的校验规则**（例如"标题不能为空"由后端 422 保证）。
5. **每次改完代码必须跑测试**，不能"看着没问题"就宣布完成。
6. **新建的测试数据自己清理**（用唯一标记 + try/finally），不要污染数据库。
7. **Windows PowerShell 里 `npm` 要写成 `npm.cmd`**，否则管道报错。
8. **Python 脚本输出中文要先 `sys.stdout.reconfigure(encoding="utf-8")`**，否则控制台乱码。
9. **修改大段代码后必须验证文件结构完整性**（本项目曾出现重复 `<script>` 块的失误）。
10. **不确定就查源码，不要猜**。报错信息指向的文件比博客可靠。

## 七、踩坑记录（同一个坑不踩第二次）

| 现象 | 根因 | 解决办法 |
|---|---|---|
| `starlette.testclient ... requires httpx2` | Starlette 1.x 换了测试依赖（老教程写 httpx） | 装 `httpx2`；或用标准库自写客户端 |
| PowerShell `Cannot run a document in the middle of a pipeline: npm` | `npm` 被解析成 .ps1 包装脚本 | 用 `npm.cmd` |
| 控制台中文显示 `�������` | Windows 控制台默认 GBK，源码是 UTF-8 | `sys.stdout.reconfigure(encoding="utf-8")` |
| Vite 报 `spawn EPERM`（受限环境） | 构建需起子进程管道 | 放宽执行权限后正常 |
| `edit` 报 `ReplaceFileW EIO (Win32 32)` | Vite dev server / 编辑器短时锁文件 | 重试；或把改动合并成一次写入 |
| `.gitignore` 加了 `.idea` 但没生效 | 文件已被 git 跟踪，规则只对未跟踪生效 | `git rm -r --cached -f .idea`（只摘索引，不删文件） |
| 测试搜"冒烟测试"返回 2 条导致失败 | 上一次测试遗留数据也命中关键词 | 用 uuid 唯一标记 + `try/finally` 自清理 |
| 数据库/接口返回的中文变乱码 | 某层用了错误字符集 | 响应链路统一 UTF-8，测试里加"中文未乱码"断言 |
